# Moonray Mesh Light in Houdini (Tier A)

Makes MoonRay **mesh lights** work in the Houdini/Solaris build and gives users a
**"Moonray Mesh Light"** LOP to author them. Status: **working in the interactive Solaris
viewport** (user-verified emitting), pending more detailed testing. See
`docs/todo.md` (the "Moonray mesh lights …" entry) for the tiered plan and open items.

- Spec: `docs/superpowers/specs/2026-07-07-moonray-mesh-light-authoring-design.md`
- Plan: `docs/superpowers/plans/2026-07-07-moonray-mesh-light-authoring.md`
- Delegate patch: `docs/patches/mesh-light-delegate.patch`

## Why this was needed (root cause)

Authoring a `MoonrayMeshLight` prim — or a standard `UsdLuxGeometryLight` — is **silently
dropped** by Houdini's UsdImaging: MoonRay never receives it as a light, and the emitter
mesh becomes plain render geometry. Cause: the `hdMoonrayAdapters` plugin (which provides
`MoonrayMeshLightAdapter`) is linked against the **standalone MoonRay USD 22.11**, not
Houdini's **USD 24.3**, and is **excluded from the Houdini build** because it fails to
compile against 24.3 (`SdfChildrenProxy::_Set`; see `research/build-issues.md`). So the
custom light prim type is never imaged.

## The approach: delegate-side carrier "piggyback"

Sidestep the dead adapter. UsdImaging **does** image the standard UsdLux light types, and
the delegate reads `moonray:class` before deriving the class from the USD type
(`Light.cc:73`). So author a **carrier `SphereLight`** (tiny radius) whose
`moonray:class="MeshLight"` overrides it to a MeshLight, and attach the emitter geometry via
a `moonray:geometry` **string** the delegate resolves itself.

```
carrier SphereLight (radius 0.01)
  + uniform token moonray:class = "MeshLight"
  + string moonray:geometry = "/path/to/emitter"
  + inputs:geometry rel      = /path/to/emitter
  + MeshLight params (inputs:*/moonray:*)
        │  UsdImaging images the SphereLight → sphereLight Sprim
        ▼
   hd_moonray delegate: Light::rdlClassName reads moonray:class → builds RDL2 MeshLight
   Light geometry handler: moonray:geometry string → emitter Rprim → RDL2 geometry → attach
        ▼
   importance-sampled MeshLight renders
```

## Two components

### 1. Delegate change (`hydramoonray/Light.cc`) — `mesh-light-delegate.patch`
- **`moonray:geometry` string fallback** in the `attrName == "geometry"` handler: when the
  `inputs:geometry` rel yields nothing (the adapter that would forward it isn't running),
  resolve the emitter from the `moonray:geometry` string, reusing
  `Mesh::geometryForMeshLight`. (Also fixed a latent bug: `SdfPath::ReplacePrefix` return
  value was discarded.)
- **Warning suppression:** `moonray:class="MeshLight"` on a carrier light is a legitimate
  override, so don't emit the "may not be compatible with USD light type" warning for it.
- Built into the **Houdini** `hydramoonray` (rebuilt + installed). The **standalone**
  variant is not yet rebuilt — see Open items.

### 2. Authoring node — `Lop::moonray_mesh_light::1.0` (generated by `gen_hda.py`)
A Python LOP HDA that authors the carrier prim so users never see the piggyback.
- **Full MeshLight parameter UI** loaded from `moonray_MeshLight.ds` (Properties / Map /
  Visibility Flags / Light Filters — the same layout/UX as the other Moonray lights),
  authored generically from each param's "Set or Create / Block / Do Nothing" control
  companion.
- **Emitter** chosen by a **USD prim-path picker** (Scene Graph Tree).
- **Always hides the emitter** — see the critical requirement below.
- **Working On toggle:** drives the carrier prim's *visibility* (the delegate ignores
  `moonray:on`, `Light.cc:224`; a light's on/off is driven by prim visibility + intensity).
- Sensible defaults: color / intensity / exposure / visible_in_camera default to
  Set-or-Create; `visible_in_camera` defaults "force off".
- Lives under the **Lights** TAB menu.

## CRITICAL requirement: the emitter must be invisible

MoonRay **rejects** a MeshLight reference geometry that is in the render layer:
`"RdlMeshGeometry cannot be referenced in a MeshLight when it is in Layer" → "MeshLight
contains no faces" → "MeshLight did not load"`. Setting the emitter `visibility=invisible`
removes it from the render layer (it's still synced as geometry). So the node **always**
hides the emitter — hiding is required, not cosmetic.

## Open items (pinned for later)

- **Standalone/farm build (deferred).** The delegate source fix is committed but the
  standalone `hydramoonray` isn't rebuilt with it yet, so farm `hd_render` / RDL export
  don't have it. Blocked on the shared `$env{BUILD_DIR}` (the `macos-release` and
  `macos-houdini-release` presets share one build tree). Do it on the next standalone
  rebuild.
- **Interactive emitter-change re-sync (FOLLOW-UP).** Moving the emitter (or toggling its
  visibility live) does not update the running render — the delegate never marks the
  referencing MeshLight dirty when the emitter changes. Fix: a mesh→light reverse map +
  `MarkSprimDirty` on referencing lights in `Mesh::Sync`. Same root cause as the
  live-visibility-toggle breakage. Non-trivial; may need iteration for MoonRay's rebuild.
- **GL viewport preview lights (FOLLOW-UP, low priority).** The carrier is MoonRay-only, so
  the GL/Storm viewport is dark.
- **Final whole-branch review** (SDD) not yet run.

## Files & how to re-run

- `gen_hda.py` — hython generator for the HDA. Regenerate:
  ```bash
  HB=/Applications/Houdini/Houdini20.5.939/Frameworks/Houdini.framework/Versions/20.5/Resources/bin
  OTLS=/Applications/MoonRay/source/openmoonray/moonray/moonray_dcc_plugins/houdini/otls
  "$HB/hython" gen_hda.py "$OTLS/Lop::moonray_mesh_light::1.0.hda"
  cp "$OTLS/Lop::moonray_mesh_light::1.0.hda" \
     /Applications/MoonRay/installs/openmoonray-houdini/plugin/houdini/otls/
  ```
- `verify_hda.py <hda>` — hython cook test: carrier contract, generic `.ds` authoring
  (scalar + tuple), default-authored params, `visible_in_camera=force off`, On→visibility,
  emitter hidden, control-"none" skipped.
- `verify_delegate.sh {houdini|standalone}` — husk/`hd_render` + RDL dump; asserts the
  MeshLight has geometry attached **and loaded** (no layer/faces warnings).
- `fixture.usda` — carrier mesh light + invisible emitter used by `verify_delegate.sh`.

Rebuild the Houdini delegate after editing `Light.cc`:
```bash
cd docs && ./build-houdini.sh -target hydramoonray -jobs 8
cmake --install /Applications/MoonRay/build --component hydramoonray
./fix-dylib-install-names.sh
```
(Restart Houdini to load the rebuilt dylib / regenerated HDA.)
